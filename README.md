# VFC-TEST

Адаптивный сайт VFC по макету «Section 6.pdf». Чистые HTML, CSS и JavaScript, без внешних зависимостей и сборки.

## Запуск

Из `/workspace/vfc_test`: `npm start` (нужны Python 3 и Node.js/npm).
Сервер слушает порт 3000. Остановить: Ctrl+C. Проверка JavaScript: `npm run check`.
Для работы формы нужен запущенный `server.py`. Статический хостинг (включая GitHub Pages) не поддерживает серверную отправку.

Разделы доступны через hash-навигацию: главная, услуги, каталог с поиском, шесть категорий продукции, четыре услуги, процесс работы, о компании, контакты и форма заявки.

## Заявки

Форма отправляет JSON на `/api/contact`, сервер проверяет поля и доставляет письмо через Resend на **nastanikol10105@gmail.com**. Получатель фиксирован на сервере. Сервер не сохраняет заявки и не журналирует их содержимое. Есть ограничение частоты: одна успешная отправка в минуту с IP.

Настройки среды:
- `VFC_MAIL_API_KEY`: ключ Resend (вводится только в защищённых настройках, никогда в Git).
- `VFC_MAIL_FROM`: разрешённый отправитель. `VFC <onboarding@resend.dev>` подходит для теста, только если получатель совпадает с адресом владельца аккаунта Resend. Для других получателей нужен подтверждённый домен отправителя.
- Разрешён исходящий HTTPS к `api.resend.com`.

`GET /api/health` показывает наличие настройки ключа, но не проверяет его действительность. Пока ключ не введён, API возвращает 503 с понятным сообщением. Ответ 200 означает принятие письма сервисом, а не подтверждение попадания во входящие. Реальная доставка без ключа не проверена. Перед публичным запуском требуется утверждённая политика обработки данных. Для масштабирования нужны внешнее ограничение запросов и защита от спама.

## Макет

Изображения извлечены из предоставленного PDF. Контактные данные и числовые показатели перенесены из макета; перед публичным запуском их следует подтвердить. Блок с отзывами предлагает обратиться к менеджеру: неподтверждённые отзывы не публикуются. Мобильная компоновка разработана для экранов от 320px.
